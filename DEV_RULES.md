# Development rules

The first runtime was rejected. This is the required repair contract, not a claim that the current tree satisfies it. The reference is the sibling scratch-pad repository. Faster end-to-end verification is the intended deviation. Documentation verification stays independent of stubbed vendor end-to-end tests.

A rule is complete only when a blocking check and a negative fixture prove it. Missing jobs must fail the rule registry check. Do not add broad ignores to make the repair pass.

Lefthook now runs exported staged-content checks, scans commit messages before Conventional Commits validation, and checks outgoing revision snapshots. Install with `bun run hooks:install`; see [the development guide](docs/development.md). The initial jobs do not yet enforce every rule in this table, and passing these jobs does not establish complete reference parity. Hook-policy and snapshot fixtures prove the implemented subset; they do not close the remaining parity work.

Product-specific reference rules such as OpenAPI/SDK parity apply when Titan exposes the corresponding capability. Their Titan equivalents must be recorded and checked; an absent feature remains an acceptance gap.

Package direction includes runtime and development manifests. Core uses only shared foundations; adapters use core, foundations and their own registered vendor SDKs. Runtime composes adapters. Product packages cannot acquire test dependencies. Test support flows downward from aggregation through factories to framework. Required package policy binds names to directories and checks every workspace. Test registrations live only in testing/unit, testing/integration or testing/e2e; contract cases use one of those tiers. Keep test-only support under testing. The flat-test gate rejects misplaced registrations and product or tooling support directories.

GitHub Actions requires explicit user authorization. Keep repository Actions disabled and verify that setting before each push. The local hook-policy gate rejects injected workflow files. General commit and push authorization does not authorize Actions.

Public offline example answer documents live under tests/*.answers.yaml to preserve the specified first-use commands. They ship with the examples. Test registrations, case tables, factories and support remain under testing.

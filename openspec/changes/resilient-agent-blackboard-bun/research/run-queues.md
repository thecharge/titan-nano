# Owner run and submission queues

The owner run-operation queue previously used the fixed 4096 allowance. Submission handling acquired that same queue twice: first for client and submission identity, then for the selected run. Exposing its allowance unchanged would make a limit of one refuse every submission before creating an agent.

The repair uses two separately bounded queues. Home settings server.max_pending_run_operations and server.max_pending_submissions each default to the central 4096 ceiling and accept integers from one through that ceiling. Their counts include active and queued entries. Submission serialization retains its identity lock while obtaining one run-operation entry. Other per-run controls use the run queue directly. The request ledger keeps its separate existing request-mutation budget. This does not promise durable scheduling or a combined count for all HTTP traffic.

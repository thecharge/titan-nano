## Integration findings to carry forward

The pinned Codex SDK serializes every config override into --config arguments. Putting a credential under mcp_servers.titan.env would put its value in the process argument list. Its env override also replaces inherited environment values. Native integration must use environment references in MCP configuration and an explicit central environment path that preserves required authentication values. Verify that behavior through the actual pinned SDK and strict vendor stubs for start and resume; never put the opaque value into config arguments.

Runner AgentPhases currently persists tasks before execution, writes ExecutionStarted before backend.start or resume, then checkpoints the worker folder after turn returns. The native lease must cover admitted tool calls and worker checkpoint validation, while revocation must finish before publication or phase completion. A lease owned only by turn would close before the checkpoint. Native credentials must also be excluded from raw vendor events, answers, errors and captured files. The existing global environment secret scanner does not automatically know a credential minted only in the owner. Add and falsify that protection explicitly. Scope ids and readable role labels do not replace the credential or current-execution check.

The snapshot dependency helper currently validates installed dependency names and versions plus matching lockfiles, but not whether the installed patch content matches the revision. That is why a stale SDK export patch reached lint and then still spent a full test run. Record a separate focused hook repair for earlier patch/setup diagnostics and failure handling; preserve the complete check set. Manual dependency refresh is setup, not completion of that repair. The normal workflow is still slower than requested.

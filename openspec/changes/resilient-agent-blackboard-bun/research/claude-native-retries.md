## Structured exhausted-credit classification

Pinned Claude Agent SDK 0.3.319 declares SDKAssistantMessage with optional error and errorCode fields and a nullable parent_tool_use_id. The shipped errorCode contract includes credits_required. Titan classifies a top-level assistant signal with that code and a billing_error or rate_limit cause as quota_exhausted. It records the original native event, releases the stopped session, preserves the logical attempt and blocks with no retry date. A person can explicitly resume after resolving the credit requirement. The existing recovery allowance still applies.

Claude's API documentation distinguishes billing problems, rate limits and spend caps. A 429 can represent either a rate limit or an exhausted monthly or workspace spend allowance. The SDK's explicit credit signal supplies the classification used here. Its api_retry message supplies a delay and status for separate transient recovery. Ordinary usage notices continue to defer to the completed result.
